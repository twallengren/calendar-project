# CHINESE_HK compiler profile

Implementation begins after the TASE integration gate. It uses the existing `ChronologyProvider` boundary and pinned ICU4J 78.3; Java core and Python consumers receive only compiled ISO artifacts and native provenance.

`CHINESE_HK` means modern Chinese calculations at fixed UTC+08:00, with civil-date mapping, over the inclusive ISO interval 1929-01-01 through 2100-12-31. The market timezone remains an independent field. ICU's documented astronomical calculation zone is GMT+8 throughout its history; restricting the profile to 1929 onward avoids implying an older Beijing local-time profile. Use an explicit fixed-offset zone and locale for all calls. [ICU ChineseCalendar documentation](https://unicode-org.github.io/icu-docs/apidoc/released/icu4j/com/ibm/icu/util/ChineseCalendar.html).

A native year is the Gregorian year in which its first lunar month begins. ICU's continuous year is internal and must not leak into YAML, CLI or artifacts; validate the mapping against ISO new-year boundaries. Month codes `M01` through `M12` and their `L` variants identify ordinary and intercalary months. Ordered month lists contain an intercalary month immediately after its ordinary counterpart. Exact dates in absent months fail; recurring selectors skip a valid but absent month. Explicit lists select ordinary, intercalary or both. Conversion must round-trip the full year/month/leap/day identity, including boundary dates in the preceding native year.

Authoritative conversion fixtures should include 1929/2100 boundaries, modern new years, 2023 leap second month, 2025 leap sixth month and the 2033/2034 transition. HKO warns of possible one-day changes where distant new moons or solar terms fall near midnight, including 2057, 2089 and 2097. Preserve and explain any ICU/HKO disagreement in tests; never silently edit the generic Hebrew provider or substitute a different Chinese epoch. [HKO conversion tables and caveats](https://www.hko.gov.hk/en/gts/time/conversion.htm).

`QINGMING_HK` is a separate bounded ISO reference table extracted from cited HKO annual tables. A reference outside its table interval fails distinctly. Native lunar calculations do not govern exchange substitution or exceptional closure policy; those remain market rules with exchange evidence. Future computed rules are projected schedules until an exchange announcement supports confirmation.

Acceptance covers independent HKO fixtures, complete native round trips, invalid dates, ordinary/intercalary recurrence, long relative offsets and narrow/wide generation equality. HKEX migration must compare complete published occurrences, explain intentional provenance changes and preserve all observed closure answers unless primary market evidence corrects them.
